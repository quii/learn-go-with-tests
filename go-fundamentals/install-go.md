# Goをインストールし、生産性の高い環境を整える

Goの公式インストール手順は、[こちら](https://golang.org/doc/install)から入手できます。

## Go 環境

### Go Modules

Go 1.11から[Modules](https://go.dev/wiki/Modules)が導入されました。この方法は Go 1.16 以降のデフォルトのビルドモードなので、`GOPATH` の使用は推奨されません。

モジュールは、依存関係管理、バージョン選択、再現性のあるビルドに関連する問題を解決することを目的としており、ユーザは `GOPATH` の外で Go コードを実行することもできます。

**少し背景を説明します: モジュール以前はどうだったのか。** Go 1.11 より前、Go のツールチェーンは `GOPATH` という慣習に依存していました。これはマシン上の単一のディレクトリ（通常は `~/go`）を指す環境変数で、すべての Go コードはそこに置かなければなりませんでした。すべてのプロジェクト、すべての依存関係、すべてのコンパイル済みパッケージがそのディレクトリ配下に保存されていたのです。つまり、コンピュータ上の好きな場所にフォルダを作って Go のコードを書き始める、ということは単純にはできませんでした。コンパイラは `GOPATH` の外にあるインポートを解決する方法を知らなかったからです。

**モジュールがそれぞれの問題をどう解決するのか。** 依存関係管理については、プロジェクト内の `go.mod` ファイルが、コードが必要とする外部パッケージとそのバージョンを明示的に宣言します。これは Node.js の `package.json` に似ています。バージョン選択については、Go は最小バージョン選択（Minimum Version Selection, MVS）と呼ばれる決定的なアルゴリズムを使います。複数の依存関係が同じパッケージの異なるバージョンを要求している場合、Go は常にすべての要求を満たす最小のバージョンを選ぶため、結果が予測可能になります。再現性のあるビルドについては、Go は `go.mod` と並んで `go.sum` ファイルを生成します。このファイルには、すべての依存関係の暗号学的ハッシュが含まれています。プロジェクトをビルドする人は誰でも、それらのハッシュで検証された、まったく同じファイルをダウンロードすることになります。リモートサーバー上で何かが変わっていれば、ビルドは即座に失敗します。

**なぜモジュールでは `GOPATH` の外にコードを置けるのか。** Go がディレクトリ内に `go.mod` ファイルを見つけると、そのファイルがプロジェクトの基点（アンカー）として機能します。ツールチェーンはそれを使ってすべてのインポートをそのモジュールからの相対で解決するため、グローバルな `GOPATH` を参照する必要がありません。つまり、マシン上のどこにプロジェクトフォルダを作っても、コンパイラはそれを理解できるのです。

モジュールの使用方法は非常に簡単です。`GOPATH`外の任意のディレクトリをプロジェクトのルートとして選択し、`go mod init`コマンドで新しいモジュールを作成します。

`go.mod`ファイルが生成されます。このファイルには、モジュールのパス、Go のバージョン、そして依存関係の要件（ビルドを成功させるために必要な他のモジュール）が含まれています。

`<modulepath>`が指定されていない場合、`go mod init`はディレクトリ構造からモジュールのパスを推測しようとします。引数を与えることでそれを上書きすることもできます。

```sh
mkdir my-project
cd my-project
go mod init <modulepath>
```

`go.mod`ファイルは次のようになります。

```
module cmd

go 1.24

```

ここで宣言されている Go のバージョンは単なる情報ではありません。より新しいバージョンの Go をインストールしていても、ツールチェーンはこのバージョンを使って、どの言語仕様（セマンティクス）を適用するかを決定します。たとえば、Go 1.22 では `for` ループ変数の挙動が変わりました。そのため、その挙動に依存するコード（後の[並行性](concurrency.md)の章で扱います）が期待どおりに動作するには、`go.mod` で `1.22` 以降を宣言する必要があります。これをある程度最新に保っておけば、後で混乱するようなデバッグをせずに済むでしょう。

組み込みのドキュメントには、利用可能なすべての`go mod`コマンドの概要が記載されています。

```sh
go help mod
go help mod init
```

## Go リンター

デフォルトのリンターに対する改良は、[GolangCI-Lint](https://golangci-lint.run)を使用して構成できます。

以下のようにインストールすることができます。

```sh
brew install golangci-lint
```

## リファクタリングとあなたのツーリング

この本では、リファクタリングの重要性を大きく強調しています。

あなたのツールは、より大きなリファクタリングを自信を持って行うのに役立ちます。

エディタを使いこなせば、簡単なキーの組み合わせで以下のことができるようになるはずです。

- **変数を抽出する/インライン変数**。魔法の値を取得して名前を付けることができるので、コードを素早くシンプルにすることができます。
- **メソッド/関数を抽出する**。コードの一部を取り出して、関数/メソッドを抽出できることが重要です。
- **リネーム**。ファイル間でシンボルの名前を自信を持って変更できるようになるはずです。
- **go fmt**。Goには、`go fmt`と呼ばれるオピニオン付きフォーマッタがあります。エディタはファイルを保存するたびにこれを実行すべきです。
- **テストの実行**。上記のいずれかを実行した後、すぐにテストを再実行して、リファクタリングが何も壊していないことを確認できるようにすべきです。

さらに、コードを扱いやすくするために、次のことができるようにしておくべきです。

- **関数のシグネチャを表示**。Goの関数の呼び出し方がわからなくなってはいけません。IDEは、関数のドキュメント、パラメータ、戻り値を表示してくれるべきです。
- **関数の定義を表示**。それでも関数が何をするのかわからない場合は、ソースコードにジャンプして自分で理解しようとできるべきです。
- **シンボルの使用箇所を探す**。関数がどのような文脈で使われているかを理解すると、リファクタリングの際の判断に役立ちます。

ツールを使いこなせば、コードに集中でき、コンテキストの切り替えを減らすことができます。
